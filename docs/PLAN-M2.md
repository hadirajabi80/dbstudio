## 0. Decisions (binding)

| # | Decision |
|---|---|
| D1 | **Two provider families.** `IDbProvider`/`IDbSession` (relational, SQL batches) stays frozen. Non-relational sources implement a new `IDataSourceProvider` (Core) with `Kind` ∈ `relational | keyvalue | document | stream`. Relational providers are wrapped (`RelationalSourceAdapter`) so one `SourceRegistry` lists everything; `ProviderRegistry` keeps working for the SQL code paths. |
| D2 | **One long-lived client per connection profile** for Redis/Mongo/Kafka (`SourceClientManager`), not one session per tab: `ConnectionMultiplexer`, `MongoClient` and `IAdminClient` are designed to be shared. Idle clients close after `connections.sourceIdleSeconds` (default 600). No `SessionInfo` is created; the Connections panel shows them as "clients". |
| D3 | **Streams** (Kafka tail, Redis MONITOR/pub-sub, Mongo change streams, log tails) are engine objects created over REST (`POST /streams`, returns `streamId`) and delivered as batched `stream.data` WebSocket events on the existing fan-out hub; the UI filters by `streamId`. Owner = the UI client id (`X-DbStudio-Client`); streams of a client that is gone for `orphanGraceSeconds` are closed (reuses `ClientPresence`). |
| D4 | **Engine modules.** New `IEngineModule { void ConfigureServices(IServiceCollection); void MapEndpoints(RouteGroupBuilder api); }` discovered by reflection over the Host's referenced assemblies (no trimming is used). Each package adds its own module class in its own project; `Program.cs` is edited once (M2-0). |
| D5 | **Dialect/provider ids:** `Dialect.PgSql` wire `"pgsql"`, provider ids `postgresql`, `redis`, `mongodb`, `kafka`. `ProviderInfo` gains `kind` and `dialect` becomes `Dialect | null` (null for non-relational). |
| D6 | **ER diagram = custom renderer, `@dagrejs/dagre` for layout** (worker). Not React Flow: it adds 6 packages (d3-zoom/drag/selection, classcat, zustand dup, xyflow system), renders every node as DOM and would push the bundle past budget; our renderer draws table cards as absolutely positioned divs inside one CSS-transformed layer, edges in one SVG, culls off-screen nodes and switches to a box-only LOD below 45 % zoom, which keeps 500 tables × 20 columns at 60 fps. Layout: dagre `rankdir=LR`, `ranksep 80`, `nodesep 30`, run in a Web Worker; > 300 tables degrade to per-schema clusters laid out separately and tiled. |
| D7 | **Drivers:** Npgsql 9.x, StackExchange.Redis 2.8.x (+ `NRedisStack` **not** used: RedisJSON/stream commands go through `db.Execute`), MongoDB.Driver 3.x, Confluent.Kafka 2.6.x (+ `Confluent.SchemaRegistry`, `Confluent.SchemaRegistry.Serdes.Avro`, `…Protobuf`; JSON Schema via `…Serdes.Json`). |
| D8 | **librdkafka packaging:** win-x64 keeps single-file + `IncludeNativeLibrariesForSelfExtract=true` (librdkafka.dll, zlib, zstd, libcurl… extract to `%TEMP%\.net` on first start; verified acceptable, same as SNI). macOS keeps `IncludeNativeLibrariesForSelfExtract=false`: `librdkafka.dylib` ships next to the apphost like `libe_sqlite3.dylib` and is signed with the app; `Library.Load` finds it because Confluent.Kafka probes the app directory. M2-K must prove all three RIDs in CI (`scripts/build.*` smoke runs `Rowlit.Engine --dev --port 0` and calls `GET /providers`, which forces the native load through `Library.VersionString`). Fallback if extraction fails on win-x64: folder layout (`PublishSingleFile=false`), electron-builder already copies `engine/publish/**`. |
| D9 | **Logs/Activity:** one workspace tab kind `logs` with two sub-views: **Logs** (server logs, engine log) and **Activity** (sessions/locks/running ops with Kill). Activity belongs here (same privileges, same per-provider source plumbing); it is a tab of the Logs view, not a dock panel. |
| D10 | **Bundle budget** raised to **1,400 KB gzipped over the M1 baseline** (`--budget-kb 1400`), with a new rule enforced by `bundle-size.mjs --initial-kb 120`: the entry chunk (`index-*.js` + its static imports) may grow at most 120 KB over the current tree; every new workspace (`er`, `redis`, `mongo`, `kafka`, `logs`, PG codegen flavours) is a `lazy()` chunk. |
| D11 | **Testing without Docker:** every engine source project ships a protocol-level fake (`FakeRedisServer` RESP2 over loopback TCP, `MongoFake` behind an `IMongoGateway` seam, `KafkaFake` behind `IKafkaGateway`) so unit tests run everywhere; Testcontainers suites (`postgres:17`, `redis/redis-stack:7.4.0-v1`, `mongo:7`, `apache/kafka:3.8.0` KRaft) are `[SkippableFact]` with the `*Backend.GetAsync()` pattern of `SqlServerBackend`. UI: MSW handlers + `fakeSocket` stream emitters per feature. |
| D12 | **Secrets:** Redis password, Mongo password/URI password, Kafka SASL password and Schema Registry secret go through `ISecretStore` as today (`password` field key); extra secrets use field keys `saslPassword`, `schemaRegistrySecret` — `ConnectionStore.Clone` strips every field whose `FormField.Type == "password"`, not just `password` (M2-0 change). |

Each `*Module.ConfigureServices` registers its provider (`AddSingleton<IDataSourceProvider, RedisProvider>()`), its services, `AddKeyedSingleton<IStreamFactory>("redis.monitor", …)`, and (Logs) `AddKeyedSingleton<ILogSource>("sqlserver", …)`.

### 2.2 Connection profiles and form specs
`ConnectionProfile` is unchanged; `props` follow each provider's `FormSpec` (§4–§6). `readOnly` means: Redis → only read commands allowed in Workbench/CLI (`CommandService` checks the `@write` flag from `redis-commands.json`) and no key edits; Mongo → no insert/update/delete/drop/createIndex; Kafka → no produce/create/delete/offset reset. Enforced engine-side with `READ_ONLY` like SQL.

### 2.3 Endpoint namespaces
`/api/v1/redis/{cid}/…`, `/api/v1/mongo/{cid}/…`, `/api/v1/kafka/{cid}/…`, `/api/v1/logs/{cid}/…`, `/api/v1/connections/{cid}/er/…` (ER layouts), `/api/v1/streams`, `/api/v1/sources`. Every `{cid}` handler calls `SourceClientManager.GetAsync(cid)` (opens lazily, 503 `SOURCE_UNAVAILABLE` with the driver message on failure, `source.client` event on open/close/broken). Long operations (`SCAN` full analysis, Mongo import/export, Kafka message search by timestamp over many partitions) are **jobs**: `202 { jobId }`, `job.progress`/`job.done`, `DELETE /jobs/{id}` cancels.

### 2.4 Streams (StreamManager)
- `IStreamFactory.CreateAsync(StreamContext ctx)` → `IEngineStream { Task RunAsync(IStreamSink sink, CancellationToken ct) }`. `IStreamSink.Push(JsonElement item)` appends to a bounded channel (`streams.maxQueuedItems`); the manager flushes every 100 ms or 200 items as one `stream.data` (items are JSON objects specific to the kind, `seq` monotonic per stream). When the channel is full the oldest items are dropped and `stream.state{state:"open", dropped:n}` is sent every second while dropping (the UI shows "dropped 1,240 lines").
- Limits: 8 streams per UI client (`STREAM_LIMIT`), hard cap 64 engine-wide. Pause keeps the stream open but drops instead of queuing (Kafka tail pauses the consumer instead). Streams end with `stream.state{ended, reason}` when the client disconnects for > `orphanGraceSeconds`, the source client breaks, or `DELETE`.
- Item shapes: `redis.monitor` `{ ts, db, client, args: string[] }`; `redis.subscribe` `{ ts, channel, pattern?, payload: string, binary?: boolean }`; `kafka.tail` = `KafkaMessage` (§6); `mongo.changes` `{ ts, operationType, ns, documentKey, fullDocument?: ejson, updateDescription? }`; `logs.tail` = `LogEntry` (§7); `activity.poll` `{ ts, sessions: ActivityRow[] }`.

### 2.5 UI generalisation summary
Explorer tree per kind (§4–§6 list the node types); tabs are `ViewTab`s with ids `redis.browser|workbench|cli|pubsub|slowlog|info|analysis`, `mongo.documents|aggregate|schema|indexes|explain|validation|import`, `kafka.overview|topics|messages|groups|produce`, `logs`, `er.diagram`; `key` = `${cid}:${view}:${path}` so re-opening activates. Workspace persistence works unchanged (`state` must be JSON; no live handles in state — stream ids are re-created on mount). Ctrl+P: module palette entries. Commands: each package registers `redis.*`, `mongo.*`, `kafka.*`, `logs.*`, `er.*` in its own `commands.ts`; context menus by `contextMenu(id, SourceTarget)` with menu ids `explorer.redis.key`, `explorer.redis.folder`, `explorer.redis.db`, `explorer.mongo.db`, `explorer.mongo.collection`, `explorer.kafka.topic`, `explorer.kafka.group`, `explorer.kafka.cluster` (M2-0 reserves them in `menuModel.ts` as `optional` entries with the command ids listed per feature).

- Scope: per schema, per selected tables (multi-select in the explorer → `er.openSelected`), or "related" set; "Add tables…" opens the object palette filtered to tables of the connection; cross-schema FKs draw the referenced table greyed ("ghost", click → add). Works for `tsql`, `plsql`, `sqlite`, `pgsql` because it uses only `CatalogObject.c/pk/fk` from loaded schemas (loads the schema via `useCatalog.loadSchema` when needed; incoming FKs from other schemas come from those schemas' `fk` arrays when loaded, else `objectDetails.referencedBy` on demand).
- Cards: header (icon, schema-qualified name when not default, row estimate when details fetched), columns with PK key badge, FK link badge, nullable "?", type text (toggle), truncated at 25 columns with "+12 more" (click expands). LOD: < 45 % zoom = header only; < 20 % = coloured box with name on hover. Edge = cubic path from the FK column row to the referenced PK row (recomputed when a card moves); cardinality glyphs: many side crow's foot, one side bar; dashed when the FK column is nullable (optional). Self-references loop on the right. Hover an edge → tooltip with constraint name and column pairs; hover a card → highlight its edges and neighbours, fade the rest.
- Interaction: wheel = zoom at cursor (0.1–3×), Space/middle drag or two-finger = pan, drag card = move (saved), `Shift`+drag = marquee select, `Ctrl+A`, arrows move selection by 8 px, `F` fit, `0` 100 %, `Delete` removes from diagram (not from the database), `Enter` opens data (`data.open`), `F4` design, `Ctrl+F` search (zooms to and pulses the match), `Tab`/`Shift+Tab` cycles cards in reading order (keyboard-first: cards are focusable `role=button` in an `aria-label`ed `role=application`). Minimap (bottom-right, 180×120, click/drag to navigate). Context menu on card: Open data, Design, Open DDL, Copy name, Show related, Remove from diagram, Pin layout.
- Drag-to-create FK: drag from a column of table A to a column of table B (only when the connection is not read-only and the dialect supports `ALTER TABLE … ADD CONSTRAINT`): opens a small dialog (constraint name, columns, ON DELETE/UPDATE) and runs through the existing designer `scriptTable` + `applyDdl` (M1.5 endpoints); on success the catalog refresh adds the edge. SQLite: disabled with tooltip "SQLite cannot add a foreign key to an existing table".
- Export: PNG (render cards and edges to an offscreen canvas at 2×, honouring the current theme; `platform.showSaveDialog`) and SVG (serialise the edge SVG + foreignObject-free card markup built from the model, embedded CSS from tokens). Both export the whole diagram, not the viewport.

Auto layout ("Auto ▾": Layered LR, Layered TB, Grid) re-runs dagre in `er/layout.worker.ts`; manual moves set `positions`; "Reset layout" clears. A layout is saved per (connection, database, scope key) and debounced 800 ms.
- Files: `ui/src/components/ErDiagram/{ErDiagramView.tsx, ErCanvas.tsx, TableCard.tsx, EdgeLayer.tsx, Minimap.tsx, DetailsPane.tsx, model.ts (graph build from CatalogSnapshot), layout.worker.ts, layout.ts, edges.ts (path + anchor math), exportPng.ts, exportSvg.ts, fkDialog.tsx, commands.ts, er.css, __tests__/*}`, `ui/src/api/er.ts` types (M2-0 provides stubs), engine `engine/src/DbStudio.Core/Diagrams/DiagramStore.cs`, `Host/Endpoints/DiagramEndpoints.cs` (M2-ER owns; registered via an `IEngineModule` in Core named `DiagramsModule`).

### 8.1 Model and endpoints
```ts
interface LogSourceInfo { id: string; title: string; kind: 'log'|'activity'; supportsTail: boolean; supportsRange: boolean; levels: string[]; needs?: string /* privilege hint */; available: boolean; reason?: string }
interface LogEntry { ts: string | null; level: 'debug'|'info'|'warn'|'error'|'fatal'|'unknown'; source: string; message: string; detail?: string | null; fields?: Record<string, string>; seq: number }
interface LogQuery { sourceId: string; from?: string; to?: string; levels?: string[]; q?: string; limit: number /* ≤ 5000 */; before?: number /* seq cursor */; archive?: number /* SQL Server log file index */ }
interface ActivityRow { id: string; kind: 'session'|'op'|'lock'|'client'; user?: string; host?: string; app?: string; database?: string; state: string; since?: string; durationMs?: number; waitType?: string; blockedBy?: string; command?: string; text?: string; cpu?: number; reads?: number; canKill: boolean; fields?: Record<string,string> }
```
- `GET /logs/{cid}/sources` → `LogSourceInfo[]` (per provider, probing privileges once per client with a cheap call; cached 5 min; `available:false` + `needs` when denied). `POST /logs/{cid}/query { LogQuery }` → `{ entries, hasMore, truncated }`. Streams: `logs.tail { sourceId, levels, q }` (engine polls at `logs.tailIntervalMs` with a per-source cursor: last timestamp/seq; Redis MONITOR and Mongo change streams are true pushes), `activity.poll { intervalMs: 2000 }` → `ActivityRow[]` snapshots. `POST /logs/{cid}/kill { id, kind }` (danger; `KILL spid`, `ALTER SYSTEM KILL SESSION 'sid,serial#'`, `pg_terminate_backend`, `CLIENT KILL ID`, `db.killOp`), `POST /logs/{cid}/export { LogQuery, format: 'txt'|'csv'|'json', path }` → file/job. Engine log source id `engine` (`GET /logs/engine/...` with `cid = engine`): reads the Serilog file(s) under `AppPaths.LogsDir` with a tail cursor; `engine.log` WS events are also appended live.
- Per provider (`ILogSource` keyed by provider id, each a new file in that provider's project; activity in `IActivitySource`):
  - **SQL Server**: `errorlog` (`xp_readerrorlog @p1=file, @p2=1, @p3=search, @p4=NULL, @p5=from, @p6=to, @p7='desc'`; archives from `sp_enumerrorlogs` → `archive` param; level from text: "Error:"/severity ≥ 16 → error, "Login failed" → warn), `agentlog` (`xp_readerrorlog …,2` when Agent exists), `system_health` (XE ring buffer: `sys.dm_xe_session_targets` target_data XML parsed for `error_reported`, `wait_info`, `xml_deadlock_report` → entries with `fields`), `default_trace`? no. Needs: `VIEW SERVER STATE` (XE), `securityadmin`/`sysadmin` for `xp_readerrorlog` (surface as `needs`). Activity: `sys.dm_exec_sessions` + `sys.dm_exec_requests` + `sys.dm_exec_sql_text` + `sys.dm_tran_locks` summary (blocking chain via `blocking_session_id`), kill = `KILL n`.
  - **Oracle**: `alert` (`V$DIAG_ALERT_EXT WHERE component_id='rdbms' AND origin_timestamp BETWEEN … ORDER BY originating_timestamp DESC FETCH FIRST :n ROWS ONLY`; `message_level` 1→error, 2→warn, 8/16→info; fallback 11g: `X$DBGALERTEXT` is SYS-only → `available:false`, needs `SELECT on V_$DIAG_ALERT_EXT`), `audit` (`UNIFIED_AUDIT_TRAIL` when granted, optional). Activity: `V$SESSION` join `V$SQL`, `V$SESSION_WAIT`, blocking via `BLOCKING_SESSION`; kill `ALTER SYSTEM KILL SESSION 'sid,serial#' IMMEDIATE` (needs `ALTER SYSTEM`).
  - **PostgreSQL**: `serverlog` (`pg_ls_logdir()` → newest files; `pg_read_file(path, offset, length)` paged by byte offset with a line parser that understands `log_line_prefix` defaults `%m [%p]` and csvlog/jsonlog when `log_destination` says so; needs `pg_read_server_files`/`pg_monitor` or superuser; cloud providers without file access → `available:false` with reason), `pg_stat_statements` (optional source: top statements as entries). Activity: `pg_stat_activity` (+ `pg_blocking_pids`, `pg_locks` summary, `wait_event_type/wait_event`), kill `pg_cancel_backend`/`pg_terminate_backend` (two actions; needs `pg_signal_backend`).
  - **Redis**: `slowlog` (SLOWLOG GET 128, cursor by id), `latency` (`LATENCY LATEST` + `LATENCY HISTORY event`; needs `latency-monitor-threshold > 0`, shown as a hint with a one-click `CONFIG SET` when not read-only), `monitor` (live only; warning banner "MONITOR costs ~50 % throughput on busy servers", auto-stops after 10 minutes unless extended). Activity: `CLIENT LIST` (idle, cmd, flags, age), kill `CLIENT KILL ID`.
  - **MongoDB**: `getLog` (`{ getLog: 'global' }` → last 1024 lines; parsed JSON log lines (4.4+) give `t.$date`, `s` severity, `c` component, `msg`, `attr`; needs `clusterMonitor`), `profiler` (`system.profile` of a chosen database; `profile` level shown with a setter `db.setProfilingLevel` guarded; entries with `millis`, `ns`, `command`), `changes` (change stream as a log). Activity: `$currentOp` aggregation (`{ allUsers: true, idleConnections: false }`), kill `killOp`.
  - **Kafka**: `client` (librdkafka log/error callbacks captured per client handle, ring buffer 5000) — the protocol offers no broker log; documented. Activity: fetch/tail jobs + consumer groups.
  - **SQLite**: no sources (`[]`); the Logs tab shows the engine log only.

### Engine
- **Composition root:** add a public `sealed class XxxModule : IEngineModule` (`Core/Providers/IDataSourceProvider.cs`) in your project. `EngineModules.Discover(ModuleAssemblies.All)` (`Core/Services/EngineModules.cs`, roots in `Host/ModuleAssemblies.cs`) instantiates every module of the Rowlit assemblies; `ConfigureServices` runs before `Build()`, `MapEndpoints(api)` after, on the `/api/v1` group. Skeletons: `RedisModule`, `MongoModule`, `KafkaModule`, `LogsModule`. A new module in Core (M2-ER `DiagramsModule`) needs no Host change.
- **Providers:** `services.AddSingleton<IDataSourceProvider, RedisProvider>()` (already done by the skeleton modules; replace the stub bodies). `SourceRegistry` (`All`, `Get`, `Find`, `KindOf`, `IsRelational`, `DialectOf`, `Describe`) lists them next to the relational providers (`RelationalSourceAdapter`); `GET /providers` and `POST /connections/test` go through it.
- **Clients:** `SourceClientManager.GetAsync(cid, ct)` (lazy open, one open at a time per connection, 503 `SOURCE_UNAVAILABLE` on driver failure, `source.client` events), `MarkBrokenAsync(cid, reason)`, `CloseAsync`, `Peek`, `Info`, `List`, `AcquireLease(cid)` (keeps a client from the idle reaper; `connections.sourceIdleSeconds`). Cast the result to your client class (`RedisClient`, `MongoClientHandle`, `KafkaClientHandle`).
- **Secrets (D12):** password-typed form fields never reach `connections.json`; `password` stays the main secret, every other password field is stored under `ConnectionStore.SecretKey(id, key)`; `ConnectionStore.WithSecrets(profile)` restores them (the client manager passes that copy to `OpenAsync`). Prop value `null` clears, `""`/missing keeps.
- **Streams:** `services.AddKeyedSingleton<IStreamFactory, MonitorStreamFactory>("redis.monitor")`. `IStreamFactory.CreateAsync(StreamContext, ct)` validates `ctx.Params` (`GetString/GetInt/GetBool/GetStrings`) and returns an `IEngineStream` whose `RunAsync(IStreamSink, ct)` pushes JSON objects (`sink.Push(item)` / `sink.Push<T>(dto)`) until cancelled; implement `IPausableEngineStream` to pause the source instead of dropping, `IAsyncDisposable` for cleanup. `StreamManager` (`Core/Services/StreamManager.cs`) batches (100 ms / 200 items, `seq` per batch), drops the oldest items beyond `streams.maxQueuedItems` and reports `stream.state{open, dropped}` every second, enforces 8 per UI client / 64 total (429 `STREAM_LIMIT`), and ends streams with the reasons `closed`, `client-gone`, `source-closed`, `source-broken`, `completed`, `shutdown` (`error` + message when `RunAsync` throws). `connectionId = "engine"` (`StreamManager.EngineConnectionId`) is allowed for engine-level streams.
- **Jobs:** `JobManager.Start(kind, cid, http.ClientId(), async (ctx, ct) => { ctx.Report(done, total, message); return result; })`, then answer `Results.Json(new JobStarted(id), CoreJson.Options, statusCode: 202)`; events `job.progress` / `job.done{status, error, result}`; `DELETE /jobs/{id}` cancels, `GET /jobs` lists.
- **Errors:** `EngineException.SourceUnavailable(msg)`, `.StreamLimit(msg)`, `.Privilege(msg, needs)`, `.ReadOnly(connectionName, action)`; codes in `ErrorCodes` (`SOURCE_UNAVAILABLE`, `STREAM_LIMIT`, `PRIVILEGE`, `GROUP_ACTIVE`).
- **Framework endpoints:** `Host/Endpoints/StreamEndpoints.cs` (`/streams`, `/jobs`), `SourcesEndpoints.cs` (`/sources/clients`, `/sources/{cid}/client`), DTOs in `Host/Contracts/M2.cs`. Editing or deleting a connection closes its source client; deleting also ends its streams.
- **PostgreSQL:** stub classes registered in `Program.cs` (`PostgreSqlProvider`, `PgConnectionStrings` with the final form spec, `Designer/PgDdlScripter`, `Designer/PgDesignerDatabase`, `Plans/PgPlanReader`, `Params/PgParamBinder.Instance`, `PgReservedWords`) throw `NotSupportedException` until PG-A implements them; `Dialect.PgSql` (`"pgsql"`), `DialectInfo`, `SchemaInfo.SearchPathIndex` and the settings dialect `pgsql` are in place. PG-A still owns the Core switch edits of §4.
- **Tests:** skeleton test projects `DbStudio.Providers.PostgreSql.Tests`, `DbStudio.Sources.{Redis,Mongo,Kafka}.Tests`, `DbStudio.Logs.Tests` (one test each, xunit + `Xunit.SkippableFact`); framework tests in `engine/tests/DbStudio.Core.Tests/M2/SourceFrameworkTests.cs` (`FakeSourceProvider`, `FakeStreamFactory`, `GatedPublisher` are reusable patterns). Feature packages add their own driver and Testcontainers package references.
- **Docker:** every service block is in `engine/tests/docker/compose.yml`; the seed files committed by M2-0 are placeholders (`seed-postgres.sql`, `seed-redis.sh`, `seed-mongo.js`).
- **CI:** `scripts/ci/kafka-native-smoke.mjs <engine exe>` runs after publish on Windows and macOS (checks `GET /providers`; M2-K adds the librdkafka check). Optional `integration` job via `workflow_dispatch` (`integration=true`).

### UI
- **Wire types:** shared framework types in `ui/src/api/types.ts` (`SourceKind`, `StreamKind`, `StreamOpenRequest`, `StreamInfo`, `SourceClientInfo`, `JobStarted`, WS events `stream.data|state`, `source.client`, `job.progress|done`); feature types in `ui/src/api/types.m2.ts` (one section per package, re-exported from `types.ts`); ER helpers in `ui/src/api/er.ts`.
- **REST:** `api.openStream/closeStream/pauseStream/resumeStream/listStreams`, `api.sourceClient/closeSourceClient/sourceClients` and `api.cancelJob` in `client.ts`; the feature namespaces `api.redis|mongo|kafka|logs|er.*` are written in `ui/src/api/client.m2.ts` (`createM2Namespaces`, one section per package; keep every path a literal template, because `mocks/m15/mockRoutes.test.ts` reads them).
- **WebSocket:** `engineSocket.onStream(streamId, fn)`, `engineSocket.onJob(jobId, fn)`; on an engine restart every stream subscriber receives `stream.state{ended, reason: 'engine-restarted'}` (`endAllStreams`).
- **Source modules:** `registerSourceModule({ providerId, kind, tree, contextMenuId, activate, defaultWorkspace, paletteEntries, ensureLoaded?, icon?, onDisconnect? })` in `ui/src/lib/sources.ts`; build rows with `sourceRow(...)` (ids via `sourceNodeId`) and call `notifySourceTreeChanged()` when the data changed. Register from your `components/<Feature>/commands.ts` (auto-loaded by `commands/index.ts`) and keep views behind `lazy()`. The explorer (`Explorer/tree.ts` `addSourceChildren`, `Explorer.tsx` `contextMenuIdOf` / `activateRow` / `targetOfRow`) delegates `kind: 'source'` rows; commands receive a `SourceTarget` (`commands/types.ts`, `isSourceTarget`).
- **Shell helpers:** `providerKind`, `kindOf`, `isRelational`, `hasDatabaseLevel`, `dialectOrNull`, `useSourceKind` in `store/connections.ts`; `useSourceClients` (`store/sourceClients.ts`); `connectAndOpen` opens `defaultWorkspace` for non-relational connections; `preloadCatalog` / `effectiveDatabase` / `catalogDatabase` are no-ops / null for them; Ctrl+P prefixes `k:` (Redis keys), `coll:` (Mongo collections) and `t:` (tables and Kafka topics) via `paletteEntries`.
- **Menus:** `view.logs` (**Mod+Alt+Shift+L**, a deviation: Mod+Alt+L is already the second Format SQL binding) and `er.open` (Mod+Alt+E) in the View menu; the context menus `explorer.sourceConnection`, `explorer.redis.{db,folder,key}`, `explorer.mongo.{db,collection}` and `explorer.kafka.{cluster,topic,group}` reserve the command ids (optional until the owning package has a `commands.ts`, see `ownerLoaded` in `commands/commands.test.ts`).
