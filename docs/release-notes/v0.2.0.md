**DbStudio 0.2** adds **PostgreSQL** as a fourth SQL database, workspaces for **Redis, MongoDB and Kafka**, an **ER diagram** and **server logs & activity**, all in the same keyboard-first app.

## Highlights

- **PostgreSQL**: explorer, `search_path`-aware IntelliSense, live diagnostics that never execute your statement (`PREPARE` in a read-only, rolled-back transaction), manual transactions with a savepoint per statement (one failed statement no longer aborts the whole transaction), `$1` / `:name` / `@name` parameters, NOTICE messages, `EXPLAIN (FORMAT JSON)` plans, table designer, formatter and code generation.
- **ER diagram** (Ctrl+Alt+E): a schema, a selection, or a table and its foreign-key neighbours, for SQL Server, Oracle, PostgreSQL and SQLite. Auto layout, saved positions, minimap, search, 500+ tables stay smooth, drag a column onto a table to create a foreign key, export to PNG or SVG. `er:` in Ctrl+P opens the diagram around a table.
- **Redis**: key browser with folders and TTL countdown, an editor for every type (strings with JSON/hex, hashes, lists, sets, sorted sets, streams with consumer groups, ReJSON), workbench with command completion, CLI, Pub/Sub, slowlog, info dashboard and memory analysis. Standalone, cluster and sentinel.
- **MongoDB**: documents as list, JSON or table with exact Extended JSON round trips, filters with field and operator completion, aggregation builder with per-stage previews and code export in five languages, schema analysis, indexes, validation rules, explain with COLLSCAN warnings, import and export.
- **Kafka**: cluster overview, topics and configs, a message browser by offset or time with JSON, Avro and Protobuf decoding (Schema Registry), live tail, produce with headers, consumer groups with lag and safe offset resets (dry run first, refused while the group is active).
- **Logs & activity** (Ctrl+Alt+Shift+L, or *Activity* in the Connections panel): SQL Server error log and system_health, Oracle alert log, PostgreSQL server log, Redis slowlog/latency/MONITOR, MongoDB log and profiler, the Kafka client log, with filters, live tail and export; an Activity grid of sessions, locks and blocking chains with Kill. A missing privilege shows the exact GRANT to ask for; the MongoDB profiler can be turned on from its hint.
- **Sample databases**: one `docker compose` file starts seeded SQL Server, Oracle, PostgreSQL, Redis, MongoDB and Kafka servers to try everything (see the README).

## Improvements

- Oracle: `NUMBER(p,s)` columns with up to 15 digits are exact decimals again (they were shown as floating point).
- Kafka: consumer-group calls retry the brief "not coordinator" answers a broker gives right after a group is created.
- Native menu shortcuts act on what has focus: F4 on an ER card or in a Data tab designs that table.
- Escape in an editor inside a dialog closes the editor's suggestion or find box first, not the dialog.
- Lazy views show a loading placeholder; the window title no longer repeats the connection name; engine error toasts link to the engine log.
- Deleting a connection also deletes its saved ER diagram layouts.

## Install notes

- **Windows**: the installer is not code-signed yet, so SmartScreen shows "Windows protected your PC". Click **More info → Run anyway**.
- **macOS**: the app is not notarized yet. After dragging it to Applications, right-click **DbStudio → Open** the first time, or run:
  `xattr -dr com.apple.quarantine /Applications/DbStudio.app`
- Upgrading keeps your connections, history and settings. Redis, MongoDB and Kafka passwords (including SASL and TLS key passwords) are stored like the others: DPAPI on Windows, the Keychain on macOS.

## Known limitations

- Kafka exposes no broker log over its protocol; the Logs tab shows DbStudio's own client log and the Activity tab its jobs, streams and consumer groups.
- SQLite has no server log; its Logs tab shows the engine log only.
- PL/pgSQL bodies inside `$$ … $$` are kept as written by the formatter (the surrounding statement is formatted).
- Redis cluster nodes running in Docker announce container addresses, so a cluster in Docker Desktop is only reachable from inside its network.
