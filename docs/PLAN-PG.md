## 0. Decisions (opinionated, binding unless a package finds a blocker)

| # | Decision |
|---|---|
| D-PG1 | New `Dialect` member `PgSql`, wire token `"pgsql"`; new provider id `"postgresql"`, display name `PostgreSQL`. |
| D-PG2 | Driver: **Npgsql 9.x** (plain `NpgsqlConnection`, no `NpgsqlDataSource`), sessions with `Pooling=false`, catalog/designer/diagnostics connections pooled. Tests: **Testcontainers.PostgreSql 4.16.0** (same line as `Testcontainers.MsSql` in `engine/tests/DbStudio.Providers.SqlServer.Tests/DbStudio.Providers.SqlServer.Tests.csproj`), image `postgres:17`. |
| D-PG3 | Manual transaction mode uses **a savepoint per statement** (`SAVEPOINT dbstudio_stmt` before, `RELEASE` on success, `ROLLBACK TO` on error/cancel). The transaction never enters the `25P02` "aborted" state; the user keeps earlier work and sees an engine message. No "aborted, roll back" UI state is needed. |
| D-PG4 | Parameters: every placeholder (`$n`, `:name`, `@name`) is rewritten by the PG binder to positional `$n` and bound as unnamed `NpgsqlParameter`s (Npgsql positional mode). `?` is **never** a placeholder in pgsql (it is the jsonb operator). String/`null` params bind as `NpgsqlDbType.Unknown` so the server infers the type like a quoted literal. Server error positions are mapped back from the rewritten text to the user's text by token alignment. |
| D-PG5 | Server diagnostics: **ship `PgPrepareDiagnostics`** (engine name `pg-prepare`): `BEGIN READ ONLY; PREPARE … AS <stmt>; ROLLBACK` per query/DML statement on a dedicated pooled connection with `-c default_transaction_read_only=on -c statement_timeout=3000`. PREPARE parses, resolves names and plans but never executes, and the transaction is always rolled back, so it is safe. DDL, `DO`, `CALL`, `COPY`, transaction/session statements are never sent (classifier gate). |
| D-PG6 | Changing the database of a tab: PostgreSQL cannot switch database on a connection, so `POST /sessions/{sid}/database` **reopens the session in place** (same session id, new connection, 409 `TX_OPEN` when a transaction is open) via a new `SessionManager.ReopenWithDatabaseAsync`. The UI needs no change (it already falls back on `NOT_SUPPORTED`, but the reopen keeps results/tab bindings keyed by session id stable). |
| D-PG7 | Name resolution uses `search_path`: the snapshot gains an optional `searchPath: string[]` (from `current_schemas(true)` minus `pg_catalog`), the UI resolves unqualified names in that order, then every loaded schema. Unquoted identifiers fold to **lower** case (new `caseFolding: 'lower'`). |
| D-PG8 | Explain: `EXPLAIN (FORMAT JSON, VERBOSE, COSTS [, ANALYZE, BUFFERS])`. Actual mode executes the statement (EXPLAIN ANALYZE discards its output, so no rows are delivered; the plan warns about it). The UI already asks "Run and explain" for non-read-only SQL. `ExecPlanPayload.rawFormat` gains `'json'`. |
| D-PG9 | Catalog scope: `pg_catalog`/`information_schema` are never loaded as schemas; a static JSON of the ~30 most used system views ships with the UI as builtin objects. Partitions (`relispartition`) are hidden; partitioned parents, foreign tables and regular tables all map to `t: 'table'`. |
| D-PG10 | Formatter: PL/pgSQL bodies inside `$$ … $$` are emitted **verbatim** in v1; the `CREATE FUNCTION/PROCEDURE … LANGUAGE plpgsql AS $$` header/footer and `DO $$ … $$;` are laid out. Inner-body formatting is a follow-up (it needs an exemption from the token-equality safety check for dollar-quoted strings). |
| D-PG11 | Contract edits (C# `Dialect` + JSON converter, `ui/src/api/types.ts`, the few Core `switch`es) are made **by PG-A in its first hour and committed before anything else**; PG-B and PG-C start from that commit. |

### 2.2 Session (`PgSession : AdoSessionBase`)

- Constructor subscribes `_conn.Notice += OnNotice`; `PingSql = "SELECT 1"`; `AutoCommitAfterBatch = false` (Npgsql autocommits outside `BeginTransaction`).
- **Notices**: `OnNotice(object, NpgsqlNoticeEventArgs e)` → `EmitMessage(sev, text, line, code: null, MessageSource.Server)` where sev = `Severity` in {`WARNING`} → Warning, else Info (`NOTICE`, `INFO`, `LOG`, `DEBUG`); text = `MessageText` + (`Detail` → `\nDETAIL: …`) + (`Hint` → `\nHINT: …`) + (`Where` → `\nCONTEXT: …`, this is what carries "PL/pgSQL function f() line 3 at RAISE"); line = `e.Notice.Position > 0 ? PgErrors.LineOf(batch, position) : null`. Notices arriving while `CurrentBatch is null` (e.g. during reopen) are dropped.
- **Errors**: `MapException`: `PostgresException pg` → `PgErrors.FromException(pg, batch, rewrittenText)`: `Code = pg.SqlState`, `Message = pg.MessageText`, `Detail` = joined Detail/Hint/Where/InternalQuery, `Line/Col` from `pg.Position` (1-based char offset into the command text that was sent) mapped back to the user's batch text through `PgSqlText.MapPosition(sentText, batch.Sql, position)` (token alignment, see 2.4), then `ToDocumentLine/ToDocumentCol`; no position → `FirstCodeLine(batch, Dialect.PgSql)`. `InternalPosition` (errors inside SQL functions) goes to `Detail` only. `57014` (query_canceled) after our own cancel is already swallowed by the base (`_cancelRequested`). `IsConnectionBroken`: base check plus `pg.SqlState is "57P01" or "57P02" or "57P03" or "08000"-"08006"` or `NpgsqlException { IsTransient: true }` with a closed connection.
- **Rows affected**: override `ReportRowsAffectedAsync` to no-op and, in `OnBatchCompletedAsync`, read the reader statistics captured in `ExecuteReaderAsync`: `((NpgsqlDataReader)reader).Statements` → for each `NpgsqlBatchCommand` with `StatementType` in {Insert, Update, Delete, Merge, Copy, Move?} emit `EmitRowsAffectedAsync(s.Rows, s.StatementType.ToString().ToUpperInvariant())`; `Select`/`Call`/`CreateTableAs` are not reported (CREATE TABLE AS could report rows — keep as `SELECT INTO` kind when classifier says so). Capture `Statements` in `OnResultSetTruncatedAsync`/after `CloseAsync` by keeping a reference to the reader in `BatchContext.Items["pg.reader"]` (the base disposes it after `CloseReaderAsync`; `Statements` remains readable after close — verify with Npgsql 9; fallback: `reader.RecordsAffected` total with `ClassifyAffected`).
- **Multiple result sets**: one batch may contain several statements (`SELECT 1; SELECT 2` from "run selection"); Npgsql returns them through `NextResult()` — nothing to do. Note for docs: Npgsql sends all statements of one command before a single `Sync`, so the whole command is one implicit transaction in Auto mode (an error in statement 2 undoes statement 1 of the same batch) — identical to psql `-c`.
- **Transactions**:
  - Auto mode: autocommit. Detect user-typed `BEGIN`/`COMMIT` with `QueryServerTransactionOpenAsync`: `SELECT xact_start IS NOT NULL AND xact_start <> query_start FROM pg_stat_activity WHERE pid = pg_backend_pid()` (inside an explicit block `xact_start` is the `BEGIN` time and differs from the check statement's `query_start`; outside, both equal the check's own start). Run after every batch (as SQL Server runs `SELECT @@TRANCOUNT`).
  - Manual mode (D-PG3): base calls `BeginTransactionAsync` (Npgsql sends `BEGIN` with the first command). In `ConfigureCommand` when `Transaction is not null`: `await ExecAsync("SAVEPOINT dbstudio_stmt")` on the connection (through `CreateCommand` so the transaction is attached). In `OnBatchCompletedAsync`: status Ok → `RELEASE SAVEPOINT dbstudio_stmt`; Error/Cancelled → `ROLLBACK TO SAVEPOINT dbstudio_stmt` + `RELEASE`, then `EmitMessageAsync(Info, "Statement rolled back to its savepoint; the transaction stays open with the previous statements intact.", Engine)`. If the user's batch itself ended the transaction (classification has `COMMIT`/`ROLLBACK`/`END`, or the savepoint commands fail with `25P01` no transaction in progress), dispose `Transaction` and set it to null so the base begins a fresh one next time. Savepoint statements use `ConfigureCommand`'s own `DbCommand` creation, never the batch command.
  - Nested manual `BEGIN` typed by the user inside the engine transaction only produces a WARNING notice (forwarded as a message) — acceptable.
- **Cancel**: default `command.Cancel()` (`NpgsqlCommand.Cancel` opens a cancel connection) plus the token; the base's attention handling applies.
- **Truncation**: `OnResultSetTruncatedAsync` returns `false` (cancel the command) when the batch classification is a single Query; else `true` (drain).
- **ChangeDatabaseCoreAsync**: throws `NotSupportedException("PostgreSQL connections are bound to one database; the session is reopened")` — the endpoint handles it per D-PG6. `CurrentDatabase` = `_conn.Database`.
- **Describe**: `PrepareDescribeSql` strips trailing `;`; `DescribeBehavior` default (`SchemaOnly | KeyInfo`): Npgsql fills `BaseSchemaName`, `BaseTableName`, `IsKey` from `pg_catalog` for `KeyInfo` (one extra round trip, fine).
- `ParamBinder => PgParamBinder.Instance`; `EnterDirectMode` not needed (no info-message-on-error mode).

### 2.4 Parameters (`Params/PgParamBinder.cs`, `PgSqlText.cs`)

- `FindPlaceholders(sql)`: tokenize with `SqlTokenizer.Tokenize(sql, Dialect.PgSql)`; `Parameter` tokens: `$n` → `ParamPlaceholder("n", offset)` (positional by `ParamNames.IsPositional`), `:name`/`@name` → bare name. `?` never appears (operator).
- `RewriteCommandText(sql, placeholders)` (the new hook): assign `$k` indices — a `$n` keeps `n`; named placeholders get the next free index in first-occurrence order (same name → same index); output text replaces every placeholder with `$k`. Record the mapping in a `[ThreadStatic]`-free way: return the rewritten text and expose `PgSqlText.Rewrite(sql) → (Text, Slots: (Name, Index)[])` so the session can re-run it deterministically for position mapping (pure function of the text).
- `CreateParameter(command, p, placeholderName)`: unnamed `NpgsqlParameter` (positional mode) — but the base adds parameters in **placeholder order of first appearance**, not by `$k` index. To keep them aligned, `PgParamBinder` overrides nothing else: the rewrite assigns indices in first-appearance order for named placeholders, and for explicit `$n` the base's `Bind` iterates placeholders in text order; mixed `$2 … $1` would misalign. Therefore in `CreateParameter`, set `ParameterName = ""` and set `command.Parameters` ordering after `Bind` in the session: `PgSession.BindParameters` override calls `base.BindParameters` then reorders `command.Parameters` by slot index (`PgSqlText.Rewrite(batch text).Slots`), inserting `NpgsqlDbType.Unknown`/`DBNull` placeholders for indices that have no bound param (so `$3` without `$2` still works). Missing names stay in `BoundParameters.Missing` (the base reports them).
- Types (`ParamValues.ToClr` → `NpgsqlDbType`): int → `Bigint` (`integer = bigint` resolves; assignment cast is implicit), decimal → `Numeric`, float → `Double`, bool → `Boolean`, date → `Date` (`DateOnly`), datetime → `Timestamp` with `DateTime.SpecifyKind(…, Unspecified)`, or `TimestampTz` when the value's kind is Utc; datetimeoffset → `TimestampTz` with `.ToUniversalTime()`; time → `Time` (`TimeSpan`); guid → `Uuid`; binary → `Bytea`; string and null → `NpgsqlDbType.Unknown` (server infers; `WHERE uuid_col = $1` and `jsonb_col @> $1` both work); refcursor → `EngineException.Validation("PostgreSQL has no REF CURSOR binds; FETCH ALL FROM the cursor inside the same transaction.")`; out/inout → `Validation("PostgreSQL returns OUT parameters as a result row; bind them as in")`.
- `ReadOutput` unused (no outputs).
- `PgSqlText.MapPosition(sent, original, pos1)`: tokenize both with `SqlTokenizer` (PgSql); walk in lockstep (token i ↔ token i: identical kinds/text except `Parameter` tokens); find the sent token containing `pos1-1`; return `original token start + min(offset in token, original token length)`; before/after all tokens → clamp. Unit tests: `:id` vs `$1`, `@a`/`@a` repeated, position inside a string after a placeholder, error at position 1.
- Describe: `DescribeAsync` in the base binds unknown placeholders as `ParamKinds.Null` → `Unknown` type → the server infers from context; `SELECT $1` alone fails with `42P18` which the describe endpoint surfaces as a normal error.

### 2.5 Catalog (`PgCatalogQueries.cs`, `PgCatalogReader.cs`)

`PgCatalogReader` keeps `Dictionary<string, NpgsqlConnection>` keyed by database (pooled connection strings with `Database=` override), `ConnectionFor(database ?? profile database)`; `DisposeAsync` disposes all. Every `pg_catalog` query below is bound with `$1` (`oid` of the schema or relation); the "exact" queries:

- **Databases**: `SELECT datname FROM pg_database WHERE NOT datistemplate AND datallowconn ORDER BY datname`. **Current**: `SELECT current_database()`.
- **Default schema**: `SELECT COALESCE(current_schema(), 'public')`.
- **Schemas** (with search_path position):
  `SELECT n.oid, n.nspname, array_position(current_schemas(true), n.nspname) AS sp, (SELECT count(*) FROM pg_class c WHERE c.relnamespace = n.oid AND c.relkind IN ('r','p','v','m','f') AND NOT c.relispartition) + (SELECT count(*) FROM pg_proc p WHERE p.pronamespace = n.oid) AS object_count FROM pg_namespace n WHERE n.nspname NOT LIKE 'pg\_%' AND n.nspname <> 'information_schema' ORDER BY n.nspname` → `SchemaInfo(name, count, sp)`.
- **Schema oid**: `SELECT oid FROM pg_namespace WHERE nspname = $1` (404 when missing).
- **Relations**: `SELECT c.oid, c.relname, c.relkind, obj_description(c.oid, 'pg_class'), c.relkind = 'p' AS partitioned, c.relkind = 'f' AS foreign FROM pg_class c WHERE c.relnamespace = $1 AND c.relkind IN ('r','p','v','m','f') AND NOT c.relispartition ORDER BY c.relname` → `r/p/f` → `table`, `v` → `view`, `m` → `mview`. (Partitioned/foreign noted in `Comment` prefix `[partitioned] `? No — leave the comment clean; the details endpoint gets `Props`-free text `"partitioned table"` in `IndexDetail.Type`? Keep simple: no marker in v1.)

Ordinal in details = `row_number()` over attnum (dropped columns leave gaps).
- **PK/unique**: `SELECT con.conrelid, con.conname, con.contype, (SELECT array_agg(a.attname ORDER BY k.ord) FROM unnest(con.conkey) WITH ORDINALITY k(attnum, ord) JOIN pg_attribute a ON a.attrelid = con.conrelid AND a.attnum = k.attnum) FROM pg_constraint con JOIN pg_class c ON c.oid = con.conrelid WHERE c.relnamespace = $1 AND con.contype IN ('p','u')` (`text[]` read as `string[]`).
- **Foreign keys, both directions**:
  `SELECT con.oid, con.conname, rn.nspname, rc.relname, fn.nspname, fc.relname, con.confdeltype, con.confupdtype, (SELECT array_agg(a.attname ORDER BY k.ord) FROM unnest(con.conkey) WITH ORDINALITY k(attnum, ord) JOIN pg_attribute a ON a.attrelid = con.conrelid AND a.attnum = k.attnum) AS cols, (SELECT array_agg(a.attname ORDER BY k.ord) FROM unnest(con.confkey) WITH ORDINALITY k(attnum, ord) JOIN pg_attribute a ON a.attrelid = con.confrelid AND a.attnum = k.attnum) AS ref_cols, rc.relnamespace = $1 AS outgoing FROM pg_constraint con JOIN pg_class rc ON rc.oid = con.conrelid JOIN pg_namespace rn ON rn.oid = rc.relnamespace JOIN pg_class fc ON fc.oid = con.confrelid JOIN pg_namespace fn ON fn.oid = fc.relnamespace WHERE con.contype = 'f' AND (rc.relnamespace = $1 OR fc.relnamespace = $1)`. Outgoing rows → `ForeignKeyRef(name, cols, refSchema, refTable, refCols)` on the parent object; incoming rows feed `ReferencedBy` in details (and the UI builds `fksIn` from the referencing schema's snapshot). Actions map `a`→NO ACTION, `r`→RESTRICT, `c`→CASCADE, `n`→SET NULL, `d`→SET DEFAULT.
- **Routines** (with overloads; one `CatalogObject` per `pg_proc` row):
  `SELECT p.oid, p.proname, p.prokind, p.proretset, pg_get_function_result(p.oid), obj_description(p.oid, 'pg_proc'), l.lanname, p.pronargdefaults, p.proargnames, COALESCE(p.proargmodes, array_fill('i'::"char", ARRAY[p.pronargs])) AS modes, (SELECT array_agg(format_type(t, NULL) ORDER BY ord) FROM unnest(COALESCE(p.proallargtypes, p.proargtypes::oid[])) WITH ORDINALITY u(t, ord)) AS arg_types, t.typrelid, t.typtype FROM pg_proc p JOIN pg_language l ON l.oid = p.prolang JOIN pg_type t ON t.oid = p.prorettype WHERE p.pronamespace = $1 AND p.prokind IN ('f','p','a','w') ORDER BY p.proname, p.oid`.
  Mapping: `p` → `proc`; `f/a/w` with `proretset` or result starting `TABLE(`/`SETOF record` or `typrelid <> 0` → `tablefunc`; else `func`. `Parameters`: modes `i`→in, `o`→out, `b`→inout, `v`→in (variadic, name prefixed `VARIADIC `), `t`→ table column (becomes a `CatalogColumn`, not a param); names `proargnames[i]` or `$i`; `HasDefault` for the last `pronargdefaults` input params; a `ParamInfo("", pg_get_function_result, "return", false)` last for functions. `Columns` of a `tablefunc`: `t`/`o` args; for `RETURNS SETOF <table>` (`typrelid <> 0`) the columns of that relation via a second query `SELECT attname, format_type(...) FROM pg_attribute WHERE attrelid = $1 AND attnum > 0 AND NOT attisdropped`.
- **Sequences**: `SELECT c.oid, c.relname, obj_description(c.oid, 'pg_class'), format_type(s.seqtypid, NULL), s.seqstart, s.seqincrement, s.seqmin, s.seqmax, s.seqcycle, s.seqcache, d.refobjid::regclass::text AS owned_by FROM pg_sequence s JOIN pg_class c ON c.oid = s.seqrelid LEFT JOIN pg_depend d ON d.objid = c.oid AND d.deptype IN ('a','i') AND d.classid = 'pg_class'::regclass WHERE c.relnamespace = $1 ORDER BY c.relname` → `sequence` objects (comment gets `owned by <table>` when identity/serial-owned).
- **Types**: `SELECT t.oid, t.typname, t.typtype, obj_description(t.oid, 'pg_type'), CASE WHEN t.typtype = 'e' THEN (SELECT array_agg(e.enumlabel ORDER BY e.enumsortorder) FROM pg_enum e WHERE e.enumtypid = t.oid) END AS labels, CASE WHEN t.typtype = 'd' THEN format_type(t.typbasetype, t.typtypmod) END AS base_type, t.typrelid FROM pg_type t LEFT JOIN pg_class c ON c.oid = t.typrelid WHERE t.typnamespace = $1 AND t.typtype IN ('e','d','c','r') AND t.typcategory <> 'A' AND (t.typtype <> 'c' OR c.relkind = 'c') ORDER BY t.typname` → `type` objects; enum labels as `Columns` (`CatalogColumn(label, "enum label", false, false)`), composite attributes as real columns (second query on `typrelid`), domain → `Comment = "domain over <base>" + description`.
- **Triggers**: `SELECT t.oid, t.tgname, c.relname, pg_get_triggerdef(t.oid, true), obj_description(t.oid, 'pg_trigger') FROM pg_trigger t JOIN pg_class c ON c.oid = t.tgrelid WHERE c.relnamespace = $1 AND NOT t.tgisinternal ORDER BY c.relname, t.tgname` → `trigger` objects (`Comment` = `on <table>` + description).
- **Details** (`GetObjectDetailsAsync`): relation oid by `SELECT c.oid, c.relkind FROM pg_class c JOIN pg_namespace n ON n.oid = c.relnamespace WHERE n.nspname = $1 AND c.relname = $2`; columns (same shape as above, `$1 = oid`, `ColumnDetail` with `Default = default_expr` or generation expression, `IsIdentity`, `IsComputed`); indexes `SELECT ic.relname, i.indisunique, i.indisprimary, am.amname, i.indnkeyatts, pg_get_indexdef(i.indexrelid), pg_get_expr(i.indpred, i.indrelid), (SELECT array_agg(COALESCE(a.attname, '(expression)') ORDER BY k.ord) FROM unnest(i.indkey::int2[]) WITH ORDINALITY k(attnum, ord) LEFT JOIN pg_attribute a ON a.attrelid = i.indrelid AND a.attnum = k.attnum) FROM pg_index i JOIN pg_class ic ON ic.oid = i.indexrelid JOIN pg_am am ON am.oid = ic.relam WHERE i.indrelid = $1 ORDER BY ic.relname` (`IndexDetail.Type = amname`, `IsPrimaryKey`); FKs/referencedBy from the FK query filtered by `conrelid`/`confrelid`; triggers `WHERE t.tgrelid = $1 AND NOT t.tgisinternal`; parameters for routines (by name + optional `pg_get_function_identity_arguments` match; several overloads → first, details list all signatures in `Parameters` of the first and the UI shows the rest from the snapshot); row estimate `SELECT CASE WHEN reltuples < 0 THEN NULL ELSE reltuples::bigint END FROM pg_class WHERE oid = $1`; `Created/Modified` null (PostgreSQL does not store them).
- **DDL** (`GetDdlAsync`): table → `PgDdlGenerator.Generate` (`generated`): `CREATE TABLE s.t (` columns `name type [COLLATE] [GENERATED ALWAYS AS (expr) STORED] [GENERATED {ALWAYS|BY DEFAULT} AS IDENTITY] [DEFAULT expr] [NOT NULL]`, then `CONSTRAINT name <pg_get_constraintdef(oid, true)>` for p/u/c/f/x constraints, `)` + ` PARTITION BY …` (`pg_get_partkeydef`), then `CREATE INDEX` lines from `pg_get_indexdef` for non-constraint indexes, `COMMENT ON TABLE/COLUMN … IS '…'` lines; view → `CREATE OR REPLACE VIEW s.v AS\n<pg_get_viewdef(oid, true)>` (`stored`), mview → `CREATE MATERIALIZED VIEW s.m AS\n<pg_get_viewdef>` + indexes (`stored`); func/proc/tablefunc → `pg_get_functiondef(oid)` (`stored`; aggregates `42809` → generated `CREATE AGGREGATE` skeleton from `pg_aggregate` or a comment); trigger → `pg_get_triggerdef(oid, true) || ';'` preceded by the trigger function's `pg_get_functiondef` (`stored`); sequence → generated `CREATE SEQUENCE … AS type START WITH … INCREMENT BY … MINVALUE … MAXVALUE … [NO] CYCLE CACHE n [OWNED BY t.c]`; type → `CREATE TYPE s.e AS ENUM ('a', 'b');` / `CREATE DOMAIN s.d AS base [constraints from pg_get_constraintdef]` / `CREATE TYPE s.c AS (attrs)`; each with trailing `COMMENT ON` when present.
- `GetCompileErrorsAsync` → `[]`; `ResolvePublicSynonymAsync` → `null`.
- `ChangeDatabase` semantics for the catalog: `ConnectionFor(database)`; `GetCurrentDatabaseAsync` returns the profile database; `LoadSchemaAsync(database, schema)` runs on that database's connection; the `CatalogService` keys caches by database once `HasDatabases` includes PgSql.

### 2.6 Diagnostics (`Diagnostics/PgPrepareDiagnostics.cs`, D-PG5)

`AnalyzeAsync(sql, profile, password, ct)`: return `[]` when `profile is null`. Tokenize + `SplitStatements` (PgSql); for each statement whose `StatementClassifier` category is `Query` (SELECT/WITH…SELECT/VALUES/TABLE) or `Dml` (INSERT/UPDATE/DELETE/MERGE, incl. `WITH … INSERT`): rewrite placeholders with `PgSqlText.Rewrite`, then on a pooled diagnostics connection (`Options=-c default_transaction_read_only=on -c statement_timeout=3000 -c search_path=<profile>`; `ApplicationName="Rowlit diagnostics"`) run `BEGIN READ ONLY; PREPARE __dbstudio_diag AS <text>; ROLLBACK` as three commands (always `ROLLBACK` in `finally`). A `PostgresException` → `SqlDiagnostic(line, col, line, col + tokenLength, "error", SqlState, MessageText [+ " Hint: …"])` with `Position` mapped through `MapPosition` minus the `PREPARE __dbstudio_diag AS ` prefix length, then offset by the statement's document position. Skip (no diagnostic) for `42P18`/`42P08` (indeterminate/ambiguous parameter type) and `25006` (read-only violation cannot happen on PREPARE). `EngineName = "pg-prepare"`. Never sent: DDL, `DO`, `CALL`, `COPY`, `SET/SHOW`, transaction control, `EXPLAIN` (EXPLAIN ANALYZE would execute), `CREATE TABLE AS`/`SELECT INTO`. Budget: ≤ 20 statements per call, 3 s statement timeout; the UI already debounces 400 ms. `PostgreSqlProvider.Diagnostics = new PgPrepareDiagnostics()`.

### 2.7 Designer (`Designer/PgDdlScripter.cs`, `Designer/PgDesignerDatabase.cs`)

`GetTypes`: `smallint, integer, bigint, numeric(precisionScale, numeric(12,2)), real, double precision, boolean, text, varchar(length, varchar(100)), char(length, char(10)), uuid, date, timestamp(precision, timestamp(3)), timestamptz(precision, timestamptz(3)), time(precision), timetz, interval, bytea, json, jsonb, xml, inet, cidr, macaddr, money, bit(length), serial(other), bigserial(other)`; categories as SQL Server's. `DesignerFeatures(Identity: true, Computed: true, ClusteredIndexes: false, IncludedColumns: true, FilteredIndexes: true, OnUpdateAction: true, Comments: true, RenameColumn: true, DropColumn: true, WithoutRowid: false, Strict: false, TransactionalDdl: true, Autoincrement: false, Schemas: true)`.

`ScriptTable` (transactional `true`, no rebuild ever required): create → `CREATE TABLE s.t (\n    cols…,\n    CONSTRAINT pk PRIMARY KEY (…),\n    CONSTRAINT uq UNIQUE (…),\n    CONSTRAINT ck CHECK (…),\n    CONSTRAINT fk FOREIGN KEY (…) REFERENCES rs.rt (…) ON DELETE x ON UPDATE y\n)` then `CREATE [UNIQUE] INDEX name ON s.t USING btree (col [DESC], …) [INCLUDE (…)] [WHERE …]`, `COMMENT ON TABLE/COLUMN … IS '…'`. Column: `name type [COLLATE "x"] [GENERATED ALWAYS AS (expr) STORED] [GENERATED {ALWAYS|BY DEFAULT} AS IDENTITY (START WITH seed INCREMENT BY inc)] [DEFAULT expr] [NOT NULL]`; `Computed.Persisted=false` → warning "PostgreSQL only supports STORED generated columns" and scripts STORED; `serial`/`bigserial` type text passes through on create, on alter → warning "use identity". Alter (diff order: renames → drops → adds → types → nullability → defaults → identity → constraints → indexes → comments): `ALTER TABLE s.t RENAME TO new`, `ALTER TABLE … SET SCHEMA`, `RENAME COLUMN a TO b`, `DROP COLUMN c`, `ADD COLUMN …`, `ALTER COLUMN c TYPE newtype USING c::newtype` (warning on narrowing/incompatible), `SET/DROP NOT NULL`, `SET DEFAULT expr`/`DROP DEFAULT`, `ADD GENERATED … AS IDENTITY`/`SET GENERATED ALWAYS|BY DEFAULT`/`DROP IDENTITY IF EXISTS`, `DROP CONSTRAINT name` + `ADD CONSTRAINT …` for changed PK/UQ/FK/CHECK, `DROP INDEX s.name` + `CREATE INDEX`, `COMMENT ON … IS NULL` to clear. Several ALTERs on one table are **combined into one `ALTER TABLE … a, b, c`** when they are column/constraint subcommands (PostgreSQL allows it; one table rewrite). Identifiers through `PgSqlText.Quote` (quote unless `^[a-z_][a-z0-9_]*$` and not reserved). `ScriptView`: `CREATE OR REPLACE VIEW s.v [WITH (security_barrier)] AS\nbody [WITH [CASCADED] CHECK OPTION]`; rename → `ALTER VIEW s.old RENAME TO new` first; warning "CREATE OR REPLACE can only append columns; drop the view first to remove or retype columns". `ViewOptions.Force`/`SchemaBinding` ignored with warnings.

`PgDesignerDatabase`: `GetScriptContextAsync` → `SELECT current_setting('server_version'), COALESCE(current_schema(), 'public')`; `ReadTableAsync` from `pg_attribute`/`pg_attrdef`/`pg_constraint` (`pg_get_constraintdef` parsed for CHECK expression and FK actions from `confdeltype`), `pg_index` (`indnkeyatts` splits key vs INCLUDE columns, `indpred` → filter, `indoption & 1` → DESC, `amname`), identity from `attidentity` + `pg_sequence` (`seqstart`, `seqincrement`), generated expression `pg_get_expr(adbin)` with `attgenerated = 's'`, collation `attcollation` when non-default, comments via `col_description`/`obj_description`; `ReadViewAsync` → `pg_get_viewdef(oid, true)` body, options from `pg_views`/`reloptions` and `information_schema.views.check_option`; `ApplyAsync` → dedicated `Pooling=false` connection with `Database` override, `DdlApplyRunner { MapError = PostgresException → PgErrors.FromException(…) }`, `transactional` honoured (PostgreSQL DDL is transactional; `CREATE INDEX CONCURRENTLY`, `ALTER TYPE … ADD VALUE`, `VACUUM` in hand-edited scripts fail with the server's own `25001` and surface as `DDL_FAILED`).

### 2.8 Plan reader (`Plans/PgPlanReader.cs`, D-PG8)
